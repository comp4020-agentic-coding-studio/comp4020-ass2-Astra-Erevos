# Maintenance is more than accumulation

More history does not automatically mean a healthier model.

KEEP ADDING — new memories, new preferences, new routines, new failures

thicker ≠ wiser

MAINTAIN — check: old assumptions; prune: inactive traces; revise: changed patterns; preserve: useful failures

connected, not just collected

# Some things stay. Some things fade.

Pruning is part of care: the history stays, but its authority changes.

STILL ACTIVE — asks directly when she wants company — recent useful pattern

NEEDS REVIEW — quiet decompression after hard days — still useful, but conditional

NO LONGER USEFUL — Friday late-night check-in — routine no longer happens

prune authority, not history

# Repairs should leave traces

If you erase the failure completely, you also erase the reason the model changed.

OLD RULE — space first

FAILURE — asked for company; got space

REPAIR — named the miss

UPDATED MODEL — check current request first

TRACE RETAINED — why v1.6 exists — archived as useful evidence

A repaired failure should not disappear from the record.

</div>
